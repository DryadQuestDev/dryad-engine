### New Features

#### Localization

- **Thirteen translations.** German, Spanish, French, Italian, Japanese, Korean, Polish, Brazilian Portuguese, Russian, Turkish, Ukrainian and both Chinese scripts. English is always loaded first and the chosen language layers over it, so a partial file falls back key by key instead of printing `[key]`.

#### Interface

- **One-shot actor animations.** `{animate: "chimera lunge, mc recoil"}` or `anim=` in actor props plays `lunge`, `recoil`, `hop`, `shake`, `shiver`, `nod`, `bounce` or `flash` once, on top of the idle loop. They are events, never saved — loading a save does not replay them.
- **Richer scene grades.** A grade can now split-tone (shadows lean one colour, highlights another) and light the scene backgrounds with a sky gradient, a vignette and animated light rays. Every preset was retuned to use them — `dusk` reads as a low sun, `night` gets navy shadows and moonlit highlights, `underwater` light shafts from above, `infernal` a fire glow from below — instead of a flat colour wash. The grade docs show each preset on a sample scene. Every field is available in the object form of `{grade}`. The rays are pixi-filters' `GodrayFilter`, created only while a grade has rays.
- **`{ambient}` particles.** `{ambient: "fireflies"}`, `"motes"` or `"embers"` drifts lights over the scene backgrounds, below the actors, with an optional density (`"fireflies#0.5"`). Saved like the grade and independent of it. Also `game.setAmbient()` / `game.getAmbient()`.
- **`{screen_shake}` and `{screen_flash}`.** A decaying tremor on the scene art (backgrounds and actors together), and a colour pulse (`red`, `white`, any grade preset) that returns to the current grade. The dialogue box is untouched by both.

- **Hover cards say how to reach into them.** A footer on every hover card names the **T** key, which flips cards between peek and interactive, and shows an **On**/**Off** pill for the current state so a press reads back immediately.

#### Items

- **`remove_item` flashes.** Taking an item away from the party bag now shows the mirror of the pickup flash ("X has been removed from your inventory."), for both `remove_item: true` (the active item) and id specs. Chests and merchants stay silent.

- **Item cards compare against equipped gear.** Hovering an unequipped item in the bag, a shop or a crafting station adds a table of stat changes against what the selected character wears: ▲/▼ per stat, coloured by whether the change helps, including the stats you would lose. An item that fits several slots (two rings, three sockets) gets a column per slot, so the card shows where it is best. New `character.compareItem(item)` returns the same numbers, and the `item_compare` emitter lets a game line up stats it renames on equip.

- **Two curves for levelled gear (experience).** Each stat's new `scaling` Stat Meta picks how it grows on levelled equipment: `flat` rides `power_scale_per_level` as before, `relative` rides the slower `relative_scale_per_level` (default 0.08). Chances, percentages and speed go on the relative curve, so their numbers still climb on every drop without running into 100% dodge or crit a few levels in. rpg_battler ships the setting on all its stats. The reward service gains `scaleStats(stats, level)` and `relativeScale(level)` for anything that should scale like gear.

- **Status links in item text preview what the item grants.** The item card hands itself to the status cards it opens – a `[[status:id]]` link in its description, its consume list – and the new `status_preview` emitter lets a game rewrite the not-yet-applied status's stats first, so a levelled item's status shows its real numbers before it is applied.

- **`status_migrate` emitter.** The save-migration pass recreates statuses from their definitions, which dropped anything set on a status when it was applied. It now fires `status_migrate(character, status, previous)` for each one before adding it back, so a game can rebuild it from the instance it replaces – the status twin of `item_migrate`. The pass also keeps each status's remaining duration and source now: loading an old save (or any save in dev mode) used to refill every timed buff and debuff to its full duration.

- **`no_discard` item trait.** A per-item switch, shipped for every game by `global_essentials`: the item card's Drop choice and the reward panel's trash button stay hidden for it. Quest rarity keeps working as before; this is for story gear of any rarity that must stay in the bag. It has nothing to do with loot drops. The item card's choice now reads **Discard** (English locale) to match.

#### Scripting

- **`{no_visited: true}` choice param.** The choice is never added to the visited list, so it keeps its undimmed look however often it is picked — for repeatable options such as a stroke-the-statues sequence puzzle.

- **Scene emitters carry the anchor.** `scene_play_before`, `scene_play` and `scene_play_after` gain a fourth argument, the `&anchor` name the paragraph was reached by (`''` for a plain scene root), so a listener can react to one branch of a scene without resolving the raw line id.

- **`{set_defeated: "a, b"}` action (rpg_battler).** Marks battle definitions defeated without a victory: the clear is recorded and `battle_defeated` fires once per definition, but no `battle_finished`, rewards or delay — for fights that never happen on the page, where `win` would be a lie.

- **New `game_setting_change` emitter.** Fires from `game.setGameSetting()` and from the Game Settings menu, with `(key, newValue, oldValue)`. Muted during a save load, so a restored value never reads as a change — unlike a Vue `watch` on `game.getGameSetting()`, which fires mid-load on half-restored state.

- **Asset Meta.** Assets gain a `meta` data bag with its own editor tab, like Stat Meta and Status Meta: define a field once and every asset's form shows it, for your scripts to read as `asset.meta`.

- **New `spine_event` emitter.** Event keys authored in a spine asset's animations now reach scripts with `(asset, name, data)`, every loop pass at the animation's playing speed – a sound or a shake lands on the frame it belongs to at any `timescale`.

- **New `asset_exit` emitter.** Fires once when a staged asset starts leaving – `{asset: "!id"}`, a `clear`/`false`/`reset` or solo sweep, the scene ending – the counterpart of `asset_render`. Pair the two to give an asset a looping sound that stops when it leaves the stage.

- **Assets take the same filters as actor slots.** Image and video assets gain `brightness`, `contrast`, `saturate`, `sepia` and `hue` beside `blur`, on the template and as inline props (`{asset: "bg_mountain(sepia = 1, saturate = 0.5)"}`). Re-staging a visible asset glides every filter over its `tween`, the same as position and opacity, so a backdrop can wash out or warm up in one line.

- **Dialogue box states.** `dialogue_minimized` is the player's Ctrl+H fold as a state, so content can fold the box and a save restores it; the show-dialogue button still brings it back. `hide_dialogue` removes the box with its buttons for a staging beat (`{state: "hide_dialogue=true"}` on an `[nw]` transition paragraph) and clears itself when the next scene plays.

- **Pick the exit on removal.** `{asset: "!portrait(exit=fadeSlideLeft, exit_duration=2)"}` takes the same `(prop=val)` tail as the add form: the props land on the staged asset and the exit plays with them, so a one-off exit no longer needs a re-stage before the `!`. The transition fields were always legal inline overrides on an add or re-stage (`enter_duration`, `enter_delay`, `enter_ease`, `exit_duration`, `exit_ease`); the assets page now says so.
- **`{trait}` writes typed values.** `{trait: "peth.battle_ignore = false"}` now stores the boolean `false` for a boolean trait and a number for a number trait. It used to store the text `"false"`, which reads as true, so a boolean trait could never be switched off from content. A value that doesn't fit the trait's type is logged and skipped.
- **`_fought(battleId)` condition (rpg_battler).** True only for a battle won in actual combat. `_defeated` stays true for every route, including `{win}` after a seduction, so content can now tell a fight from the other ways a battle gets cleared.
- **Fight choices wear a badge (rpg_battler).** A choice that carries `{battle}` shows crossed swords before its label and gets the `fight-choice` row class, so a fight option reads as one next to its alternatives. `{fight: true}` gives the same badge to a choice whose battle starts in the scene it leads to. Hide `.fight-badge` in the game's CSS to drop the icon.
- **`{reveal_room: "3, 4"}` action.** Marks rooms explored without walking into them – visited and visible, their neighbors visible – the way a map, a guide or a view from a tower uncovers them. No room events run. `dungeon.room` reaches another dungeon.
- **`_room` and `_choice_visited(id)` conditions.** `_room = room5` reads the room the player stands in. `_choice_visited(~1.intro.3.1)` is true once that choice has been picked, and `_choice_visited(dungeon2.~1.intro.3.1)` asks another dungeon. It reads choices made in hindsight, for branches that never set a flag and saves made before one existed; new content should set a flag on the branch and test that.
- **`_active_item`, `_active_item_slot` and `_slot_filled` conditions.** `_active_item(rusty_key) = true` asks which item's custom choice opened the scene, `_active_item_slot(alice) = ring` where that item is worn, and `_slot_filled(alice, helmet) = false` whether a slot holds anything.
- **`block_party_inventory_persist` state.** Blocks item use, equipping and dismissing like `block_party_inventory`, but stays on until content clears it and is saved with the game. The engine resets `block_party_inventory` at every scene start and end, so it could never hold a lock across a whole area.
- **`{status}` takes stacks and a duration.** `{status: "alice->poisoned(stacks = 2, duration = 3)"}` overrides the template's values for that apply, on a first apply and on a refresh alike. Either key works alone: `poisoned(duration = 3)`.
- **`{timestamp: "x"}` action and `_turns_since(x)` condition (turn_system).** Stamp the current turn into a flag, then gate on the wait: `_turns_since(last_rest) >= 5`. A flag never stamped counts as forever ago.
- **Room hooks know where the player came from.** `room_enter_before` and `room_enter_after` gain `fromRoomId` and `fromDungeonId`. They are right across dungeons too: on arrival from another dungeon `game.getCurrentRoomId()` still names the old dungeon's room. Forced-movement mazes and one-way passages need the source room.
- **`ignore_replay` beside a `choices` menu.** `{choices: "&talk_hub", ignore_replay: true}` skips that menu in a gallery replay, so a scene that loops back into a conversation hub ends the replay instead of leading back into play.
- **Battle end emitters carry the battle id (rpg_battler).** `battle_end`, `battle_closed_before` and `battle_closed_after` gain a second argument, the battle definition's id (`null` for an ad-hoc battle), so a listener can react to one fight's outcome.
- **Choices move the story last.** A choice's `eventDelayed` actions (`enter`, `scene`, `exit`, `battle`, `loot`, `trade` and the like) now run after its other keys, in whatever order they are written. `{enter: "19", flag: "golem_free = 1"}` used to walk into room 19, and play its events, before the flag was set.
- **`ifOr` / `activeOr` keep parenthesized arguments whole.** The OR form split on every comma, so `ifOr: "_item_on(alice, ring) = true, gold > 5"` cut `_item_on(alice, ring)` in two and never matched. It now splits like `if` does.

#### Battles and loot

- **Over-cap waves split (rpg_battler).** A wave with more enemies than `max_enemy_units` (6) used to spill past the field. It now splits, in roster order, into successive waves of at most the cap.
- **Named pooled loot (experience).** `{loot: "^trash1", title: "Dusty Shelf"}` names that placement's inventory, so its window reads "Dusty Shelf" instead of the generic name.

#### Battle VFX (rpg_battler)

- A lot of new feature for Projectiles.
- **Caster animation on projectiles.** A projectile's `caster_animation` picks how the caster moves: `melee` lunges at the target in the attack pose (an impact plays on contact, a travel sprite launches at the lunge's peak), `cast` keeps the caster in place in the cast pose. Left empty, a hostile ability lunges without images and casts with them, and a self or ally ability casts – so a projectile or impact now plays the cast pose instead of the attack pose.

#### Editor

- **Stat Meta.** Stats get a `meta` bag like statuses: define custom fields in the new Stat Meta tab (after Stat Groups) and every stat form shows them; scripts read them through `game.getData("character_stats", true)`. Plugins declare fields of their own, and a plugin may fill in another plugin's fields on the stats it defines. The Status Meta tab moves to sit right after Statuses.

- **Anchor lint.** The Dungeon Content Editor flags an `&anchor` that is not the first line of a paragraph (the parser drops it), and a `{choices}` menu anchor that is not on the block's last paragraph (the menu would show as "continue").
- **Plugin save hooks.** A plugin can declare `editor_hooks` in `plugin.json`: a script whose `beforeSave(entry, ctx)` fills in or tidies an entry of the plugin's own tabs as it is saved. It may be async, and it runs on every save path (the tab form, popups, save-and-jump) but only on the entries the save changes. For a mod it also receives the core game's entry. See Plugins → Editor Save Hooks.
- **Saves no longer overlap.** A second save waits for the one in progress, and a popup shows the entry as it was written once a save finishes.
- **Back and Forward in the Docs Viewer.** Arrow buttons in the header step through the pages you opened, including jumps between plugins' docs, and return each page at the scroll position you left it. Alt+Left / Alt+Right and the mouse side buttons do the same.

- **Ability Editor.** Ability templates get an **Ability Editor** popup that puts one ability on one screen with its card rendered live beside the form.

- **Item Editor.** Item templates get an **Item Editor** popup.

- **Inventory Editor.** Inventory templates get an **Inventory Editor** popup.

- **Stat Groups tab.** A new **Characters → Stat Groups** tab, right after Stats, defines the character sheet's sections as data: an id, a title and an order.

- **Stats popup.** Character templates, statuses, item templates and skill slots get a **Stats** button beside **Art Manager**.

- **Art Manager previews statuses on a character.** Statuses, items and skill slots get a **Preview on character** picker. The entry is drawn over that template the way the game applies it, so layers keyed on the character's attributes resolve without setting those attributes on the entry. The pick is remembered in this browser for all of them and never saved. The Attributes tab adds a preview-only column for the character's own values, for checking a state such as `battle_state = cast`, and marks every attribute the entry sets, since that value overrides the character's own while applied.

- **Dismiss follows the inventory lock.** While `block_party_inventory` is set (every battle, trades), the character sheet's **Dismiss** button dims and a click says why instead of opening the confirm – dismissing hands the character's gear back to the party inventory. New locale line `dismiss_blocked`.

- **Asset visual editor covers filters and the tween.** The asset popup's Filters block carries the five new sliders beside Blur, a new Re-stage Tween block sets `tween` and `tween_ease` (and the sliders glide the preview through them), and the Spine Playback block adds the loop toggle and the timescale.

- **Filter presets.** Every list tab's filter form can save its current values as a named chip. Chips sit under the **Filters** title, and hovering **Filters** in the bookmark column lists them too; a click applies one, and the chip whose conditions match the form lights up.

- **Dark theme.** The sun/moon button at the far left of the toolbar, beside **Exit**, switches the whole editor.

#### Audio

- **Room and dungeon ambience.** Rooms and the dungeon config gain **Default Sounds** beside Default Assets. The dungeon's play anywhere in it and a room's on top while the player is there; they keep playing through scenes, stop as the player walks out, and come back after a scene that silenced them.

- **Map loops outlive scenes, as documented.** A scene's end used to stop every looping sound, including ambience started from a room or dungeon hook. Now it stops only the loops the scene itself started.

- **Fades, gain and delay.** Music tracks and sounds gain `volume`, `fade_in` and `fade_out`; sounds add `delay`, music adds `shuffle`. Each is a default on the entity and can be overridden per play with the `(prop=val)` tail assets use: `{music: "tense(fade_out=3, fade_in=1)"}`, `{sound: "rain(volume=0.4, fade_in=2)"}`, `{sound: "!rain(fade_out=3)"}`. A sound's `fade_out` also applies when the scene ends. `{music: "!"}` stops the music, with `"!(fade_out=N)"` for the fade – there was no way to stop music from content before.

- **Sounds by file path.** `game.playSounds` and `{sound}` accept a sound id or an audio file's full path.

- **Random sounds.** A sound's new `random` flag turns its files into a pool: each play picks one at random instead of playing them all in sequence – footsteps, hits, anything that repeats. With `loop`, the files follow each other in random order.

- **Sound channels.** A sound's new `channel` field makes sounds replace each other: starting one stops whatever else is playing on that channel, each over its own `fade_out`. Use it to swap one ambience for the next, or to cut a voice line off with the next one.

#### Text

- **Text pacing tags** – Ren'Py-style markers in prose steer the typing animation: `[w]` waits for a click, `[w=1]` waits a second, `[p]` waits then breaks the line, `[nw]` advances the paragraph on its own, `[fast]` shows everything before it at once, and `[cps=30]…[/cps]` / `[cps=*2]…[/cps]` change the typing rate. A click while typing now reveals up to the next `[w]` instead of the end. See **Dungeons → Text Tags**.
- **Text styling tags** – `[color=#hex]…[/color]` and `[size=1.2]…[/size]` style prose without raw HTML.
- **Named colour tags** – `[green]`, `[red]`, `[gold]`, `[pink]`, `[purple]`, `[blue]` and `[grey]`, in shades that read on the dark text panels. Each is a `.text-<name>` class a game can recolour. The engine's flash lines use them: gains green, losses red, quests and learned skills or recipes gold, and a removed item plain.
- **Text effects** – `[shake]…[/shake]`, `[wave]`, `[bounce]`, `[pulse]`, `[rainbow]`, `[glow]`, `[spooky]`, `[flicker]`, `[blur]` and `[glitch]` animate the wrapped letters. They nest, type out normally, keep each word whole when a line wraps, and are plain `.fx-<name>` CSS rules a game can restyle or extend.
- **Party lines** – `ane!: “…”` plays only while that character is in the party. Otherwise the paragraph is skipped, actions included, so one scene can carry optional companion lines for any company. The new `_in_party(ane)` condition covers the other cases, e.g. a line that plays only when Ane is away. See **Dungeons → Talking Characters**.

### Breaking Changes

- **`.flash-content .special` removed.** The engine's flash lines carry colour tags instead of `<span class='special'>`. A game line that still wraps itself in `special` shows in the plain flash colour; switch it to `[green]…[/green]`.

- **`no_scale_stats` removed (experience).** Levelled gear scales a stat only when its `scaling` Stat Meta says how. A stat with none set stays as authored, so a game's own gear stats need `flat` or `relative` to keep growing; rpg_battler's stats come set.

- **`{choose_item}` cancel no longer advances the story.** Cancel closes the picker and leaves the scene where it stood, so the `>`, `~` or `!` choice that opened it is still on screen and the player can pick again or go another way. It used to run the equivalent of a click-to-continue, which skipped the paragraph on a mis-click. `chosen_item_id` is still cleared to `''`.

- **`item.isDroppable()` renamed to `item.isDiscardable()`.** It always answered "may the player throw this away?", and the old name read like a loot-drop check. Same rule (equipped gear, quest rarity) plus the new `no_discard` trait.

- **Discard identifiers renamed – "drop" now means loot only.** Emitters `item_drop_render` → `item_discard_render` and `item_drop_before` → `item_discard_before`; the action `drop_item` → `discard_item`; locale keys `drop_item`, `item_drop_confirm`, `item_dropped`, `item_dropped_quantity` → `discard_item`, `item_discard_confirm`, `item_discarded`, `item_discarded_quantity` (a game locale override or a listener on the old names must follow).

- **Content action `{skin_layer: ...}` renamed to `{skin: ...}`.** The syntax is unchanged – `{skin: "alice->armor & helmet, bob->!cloak"}`.

- **Projectile sizes are percentages (rpg_battler).** `projectile_travel_size` and `projectile_hit_size` in the battler's Config tab are now a share of the viewport height, not pixels: a game that set pixel values (96 is 96% of the screen) must set them again. The defaults, 9 and 18, come to about 97 and 194 px at 1080p.

- **Re-playing a running loop no longer restarts it.** `{sound: "rain"}` while `rain` already loops leaves it playing where it is, instead of cutting back to the first file; a new `volume` on the repeat still applies. To restart one on purpose, stop and play it in the same action: `{sound: "!rain, rain"}`.

- **`getTrait()` keeps `false`, `0` and `''`.** On characters and items it used to read any falsy value as `null`, so an explicit `false` looked unset. Now only an unset trait is `null`, and a persistent trait whose template says `false` or `0` returns that instead of the live value.

- **Supports fight on their own (rpg_battler).** A `battle_support` character is AI-driven without `battle_ai`. Only an explicit `battle_ai: false` hands its turns to the player.

- **Projectile sounds are audio files (rpg_battler).** A projectile's `sound` and `hit_sound` are file fields (`fileType: audio`) holding one file each, not lists of sound ids; pick the file itself.
