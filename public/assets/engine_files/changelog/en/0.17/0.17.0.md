### New Features

- **The content editor checks what content names, as you type.**
  - What is checked: every id an action, a condition, a lore link or a speaker tag names is looked up in the game's data and its dungeons – assets, music, characters and slots, attribute values, items, statuses, records, scenes, `&anchors`, rooms, `$templates`, quest logs and flags – and so is every action, condition, placeholder and text effect name.
  - How it shows: a typo is underlined, amber for a warning and red for an error, and the toolbar counts them. The list offers one-click "did you mean" fixes and an **Ignore here**; the **Ignored** tab lists what a dungeon ignores, and ignores nothing needs any more. **Whole game** runs the same checks over every dungeon.
  - Saving always works; only errors ask first. **Live checks** can be switched off in the list.
- **Suggestions and hover in the content editor.** Typing inside `{…}`, `if{…}`, or after `|`, `[[` or `[` suggests what can go there – actions with their help, then the ids the action takes: assets with thumbnails, characters with faces, slots after `->`, attribute values, scenes, anchors, flags, conditions and placeholders. Ctrl+Space suggests anywhere, a paragraph's speaker included. Hovering an id shows its name, picture and where it comes from; Ctrl+click goes to it. Suggestions turn off under **Typing** in the toolbar, which now also holds the curly-quote and en-dash switches.
- **Suggestions in the debug panel.** The **Execute Actions** box suggests and describes the same way, from the running game: the scenes of the room you are in, flags it has set, characters it holds.
- **A bare condition checks that a value is set.** `if{met_bob}`, `if: "town.gate_open"` or `_in_party(alice)` with no comparison passes when the value is anything but `0`, `false` or empty, so an unset flag reads as false. Before, a condition without an operator was logged as invalid and always failed.
- **Template instances.** A character template has a new **Instances** list for scenes that need several of the same character: each row is a character id (`guard1`, `guard2`) with only the traits, attributes and stats that differ from the template. Instances are created on a new game, and on load when a save is missing them; with **Auto create** off, `{create_character: "guard2"}` or `game.createCharacter('guard2')` creates one without naming the template. `game.resetCharacter()` and the save restore that rebuilds characters on load keep an instance's overrides.
- **Blend modes on skin layers.** A static skin layer has a new **Blend mode** – `screen`, `multiply`, `overlay`, `soft-light`, `lighten`, `darken`, `color-dodge` or `plus-lighter` – that mixes it into the character's layers below it the way a Photoshop layer blend does, so smoke, glows and mist can be drawn as the artist painted them instead of flattened. A layer only blends with its own character, never with the background, the UI or another character, so it looks the same in a scene, the gallery, a face portrait and battle.
- **`character.resetLooksToTemplate()`.** Puts a character's attributes and skin layers back to their template's, keeping stats, statuses, traits and inventory.
- **Search in the gallery.** A search field above the gallery's groups filters the Characters, Assets and Scenes tabs by name. A group whose own name matches keeps all its entries, and every group with a match stays open while searching. Only shown names are searched, so an undiscovered entry never gives its real name away.
- **Item flashes open the item's card.** The scene line an `add_item`, `remove_item` or `equip` action prints – "Moonleaf has been added to your inventory!" – now names the item as an item link, as a status line already did: the name takes its rarity color, and hovering or tapping it opens the item card.
- **`freeze_timer` state (turn_system).** While it is true the map-turn clock stands still: room entries, `{turn}`, `game.getService('turns').advance()` and the Wait button stop advancing it, so statuses stop ticking, collectables stop regrowing and `turn_advanced` stops firing. The Wait button hides itself meanwhile. Set it with `{state: "freeze_timer=true"}` and back to `false` to let time run again.
- **Rooms can stop costing time (turn_system).** A new **Advance on room enter** setting in Turn Config, on by default. Turned off, entering a room no longer passes a turn, so a game whose rooms are freely visited VN screens can pass time only through `{turn}`, `game.getService('turns').advance()` and the Wait button.
- **Records link to characters.** A record has a new `character` field naming the character it is about. Once the player has met the character, the Encyclopedia entry shows a button that opens their Gallery page, and once the record is discovered, the Gallery page shows a button that opens the entry. Scripts can do the same with `game.getCharacterRecordId()`, `game.isCharacterInGallery()` and `game.openGalleryForCharacter()`.
- **Bake a face crop into a static face.** The Art Manager's Face tab has a **Bake crop to static face** button. It renders the face crop as the preview shows it – static layers or spine, with the selected layers and attributes – into a 300×300 WebP at `games_assets/<game>/<mod>/faces/<id>.webp` and sets that as `face_static`, asking first when the file already exists. The image is written at once; the new `face_static` path is kept when the entry is saved.
- **Merging (rpg_battler).** A new `merge` ability aspect lets a combatant merge into an ally: it leaves the field and the ally grows by its base health and power, keeps both bodies' remaining health, takes over its afflictions and gains a stack of the chosen status.
- **Reveal All Records & Gallery (dev mode).** A new toggle in the debug panel's Options tab shows every encyclopedia record and follow-up, every gallery character and asset, and every gallery scene as discovered, so content can be checked without playing to it. It only changes what is shown: nothing is written to the save, and switching it off brings back the player's real progress.
- **Reputation (new plugin).** What each character thinks of the player, kept as a `reputation` trait. `{reputation: "rosa -= 1"}` changes it and adds "Rosa will remember that." under the dialogue text until the next paragraph.
- **A character's own idle.** A new `idle` character trait is the loop a character plays wherever it is staged: set `float` on a bat or a moth-girl and every `{actor}` line lifts it, without `idle=` on each one.

### Breaking Changes

- **Adding and subtracting is `+=` and `-=`.** `flag`, `property`, `char`, `stat`, `resource` and `skin_style` take `=` to set, `+=` to add and `-=` to subtract: `{flag: "button_pressed += 1"}`, `{resource: "alice.health -= 10"}`. The old `>` and `<` read like the comparisons in a condition (`_item_count(x) > 0`) and are no longer accepted — a spec that still uses them is logged and skipped. `game.parseOpsSpec()` returns the same `=`, `+=` and `-=` as its `op`.
