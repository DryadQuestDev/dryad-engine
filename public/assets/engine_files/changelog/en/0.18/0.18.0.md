### New Features

- **Speaker tags stand out.** In the content editor, the `alice:` that opens a paragraph is painted as a name tag.
- **Text lands whole on a translated page.** While the browser translates the game (Chrome's *Translate to…* or Google's page widget), dialogue skips the typing animation and shows each paragraph at once, whatever the Text speed setting says. A translator works on the text that is on the page, so a paragraph still typing was translated half-written and stayed cut off. The player's setting is left as it was and applies again when translation is switched off.
- **Names stay as written on a translated page.** Character names on face badges, the dialogue speaker label, the rename field and the name tags of the player's fighters carry `notranslate`, so a page translator no longer turns a name into a word that happens to look like it. Enemy name tags stay translatable, since a foe is often named for what it is.
- **Character records show the character's face.** An Encyclopedia record with a `character` shows that character's face beside its title. Once the player has met the character, the face carries a gallery badge and clicking it opens their Gallery page, in place of the round button that did this before. A face without the badge has no Gallery page to open yet.
- **The content editor is a subtab.** A dungeon's content opens at **Dungeons → Content**, next to Config, in place of the popup over the Config form. It fills the tab, with Save in its toolbar next to Autosave; the dungeon select, Playtest, Continue and Load save in the header work from it, since no popup covers them any more, and the editor remembers the subtab you were on. The Config form leaves out the raw content field, and **Sync** in the editor's toolbar takes the place of the Synchronize Content Document button, with its results in a panel under it. A plugin popup that names the `content` subtab in its `editor_popups` gets a button next to Save.
- **The editor opens on a Start page.** It shows template cards with Visual novel first, a game name and **Create game**, links to the new Introduction pages and the sample games, and your own games. **Start** in the header comes back to it, and it replaces the Quick Start dialog.
- **A new game lands on its first scene.** Creating from a template opens the starting dungeon's Content tab. A **First steps** banner ticks off Playtest, Back to Editor, Change a line and Save, then Continue as you do them. **Hide empty tabs** is on: the header shows only the tabs your game has data in, and the empty ones wait greyed in each tab's menu and under **⋯**, which also holds the switch.
- **Templates ship their own art.** The three templates no longer borrow the Tutorial's pictures and music. A new game gets its own copy of the files it uses, in its games_assets folder. The dungeon name you type becomes the chapter's display name. Every template opens on a commented starter scene that already sets and reads a flag and plays a sound from Sounds, and none points at a Google Doc any more.
- **Replay and go back with keys.** In a playtest, **Replay paragraph** (**Shift+R**) replays the paragraph on screen and **Back one paragraph** (**PageUp**) goes back one, for example to pick the other answer of a menu. Both work with the debug panel hidden, and the game keeps the last 10 paragraphs.
- **A missing speaker or asset no longer breaks a scene.** A line whose speaker is not a character used to empty the dialogue box; it now reads as narration, prefix included. An asset missing from Assets is left out instead of stopping the rest of the paragraph's actions. In a playtest both show a marked placeholder instead, so you can write before the characters and art exist.
- **The debug panel shows where you are.** Under **Back to Editor** it names the dungeon, the room and the paragraph playing. Back to Editor opens that dungeon's Content tab with the caret on that paragraph.
- **Debug panel: Scene tab.** It lists every choice of the paragraph on screen, hidden ones included, as **Shown**, **Hidden**, **Greyed out** or **Error**, with each condition clause by clause: what it read and whether it held. It follows the game live, so changing a variable flips the card.
- **Debug panel: Variables tab.** Flags, properties and stores sit in one searchable list with kind filters, and a click on a value edits it. Constants are locked, and the engine's UI states wait behind the **State** chip. **+ Flag** sets a flag in any dungeon before anything has set it.
- **Debug panel: Problems tab.** It lists what went wrong while you played: a speaker with no character, a missing asset, an unknown action or an unknown condition. Each row names its paragraph and has **Open in editor**, and a badge on the tab counts them.
- **Debug panel: Log tab.** It lists what happened in this run, newest first: each paragraph played, each choice picked, every variable change as old → new, other actions and problems. It has a search and kind chips. ✎ opens a paragraph in the editor and ↺ goes back to it. The log lasts across Shift+R, PageUp and Continue, and clicking a flag or property in Variables shows its history.
- **Debug panel: Console.** Execute Actions is now the Console, with three modes. Action runs an action and shows what it changed, and suggests the closest name for an unknown one. Condition checks a condition clause by clause, with the content editor's suggestions for flags and conditions. Text shows how a line comes out without running its actions. Ctrl+Enter runs, and ↑ / ↓ walk a history kept per game.
- **Debug panel: edit characters and inventories.** A character's attributes, stats, resources, traits and statuses are edited in place, and inventories get counts, remove and a search to add. Each edit runs the action content would use. The edits add up into one action you can paste into your content with **Copy as action**; repeated edits net out, and Undo puts the originals back.
- **Debug panel: see what the story set.** In the Characters tab, a stat, trait or attribute the game wrote carries a small tag after its value: `=90` for a stat set with `=`, `+5` for one moved with `+=` or `-=`, `=60 +5` for both, and `story` for a trait or attribute. Hovering it says what save restoration will do and what the template holds. Clicking it forgets the write, so from the next load the field follows the template again. An edit made in the panel is a write too, so it gets a tag at once. A search field above the fields filters them and the statuses by id.
- **Debug panel: open an inventory.** The Inventories tab has **Loot** and **Trade** buttons that open the picked inventory the way `{loot}` and `{trade}` do, so a chest or a shop can be checked without walking to it.
- **Debug panel: Quests tab.** Every quest entry the content defines, by dungeon. Tick an entry to log it the way `{quest}` does, untick it to take it out of the save. Quests and entries the save holds but the content no longer has are listed as *missing*, with a button to remove them.
- **Old saves keep what the story wrote.** On load after a version bump, and on every load in dev mode, the engine rebuilds each character from its current template and then plays back what the game wrote to it. A stat set with `=` keeps that exact value, while a `+=` or `-=` lands on top of the template's current value: a template raised from 5 to 10 turns a saved 6 into 11. Traits, attributes, skin layers and abilities keep what the story set. Everything else follows the template, so a retuned stat or a recalibrated face reaches old saves without a declaration. Items pick up their template's current fields, and their traits stay as saved. The record is `character.coreWrites`, and the new `character.addStat(name, amount)` is the scripted `+=`. The Save Restoration guide now starts with this default and treats `registerSaveMigration` as the way to tune it.
- **A quest the content drops stays out of the quest log.** A save keeps quest progress by id, so a quest you renamed, merged or removed used to show up as its bare id. The log now hides it, and hides an entry the content no longer has. In a playtest each one is listed in the Problems tab, along with any `{quest}` action that logs an entry the content does not define.
- **An ability can keep its secrets.** With the new `conceal_effects` meta field on, the ability card shows the name, cooldown, costs and description, then a single *Effects unknown* line in place of the generated targeting and effect lines. The ability itself works as authored.
- **A character's record can unlock when the player meets them.** Records with a `character` have a **Reveal** setting. `talk` discovers the record silently the first time that character speaks a line in a scene; `appear` the first time they are staged or speak, whichever comes first. Either way you don't need a `{lore}` action at every place they might first turn up.
- **Snapshots.** **Shift+S** keeps the moment under a name. Load it any time, even after a reload; snapshots stay out of the save lists.
- **Play from here.** A ▷ on a scene, a column or a choice in the Content tab starts a playtest right there, from a new game or a snapshot, with values set first. A choice's own condition fills in the values it needs.
- **Playtest menu.** The arrow next to Playtest starts from the top, from the scene you are editing, or from a snapshot.
- **Debug panel: fold and resize.** **Shift+D** folds the panel to a slim strip at the window's edge and brings it back. Drag the panel's left edge to resize it; this replaces the width box. The tabs now run in task order: Scene, Variables and Problems first, Options last.
- **Scene points: clickable spots on a scene's picture.** Place named points on a picture in **General → Scene Points** (the **Visual Editor** places them by eye), switch a layout on with `{inspect: "id"}`, and give a choice `{point: "id"}`: it is drawn on the picture at that point, labeled with its own text, instead of in the menu. Picking it zooms the picture toward the point, and coming back to the menu zooms out; `{zoom: "id"}` / `{zoom: false}` move the camera without a click. Points follow the picture however it's fitted or zoomed. Scripts get `game.getScenePoints()`, `game.getActorRect()` and the `scene_point_pick` emitter. A layout with **look_button** keeps its points behind a **Look around** button until the player asks to look, and fades the actors (**hide_actors**) only while they do. See Dungeons → Scene Points.
- **New one-shot `hurt`**: `{animate: "bram hurt"}` plays the recoil and the red flash together, for a body taking damage (one-shots replace each other, so `recoil` and `flash` never stacked). The directional one-shots also take `facing`, a character on stage or `left` / `right`: `{animate: "mc lunge(facing=bram), bram hurt(facing=mc)"}` lunges toward Bram and knocks him back away from the MC, wherever the two stand. Without it they still aim at the stage center.
- **New `ui-top-center` slot**: a centered column at the top middle of the game area for scene-wide buttons and meters, stacked by `order` and hidden while the character sheet is open. The scene points' Look around button lives there.
- **A choice that appears mid-menu slides in.** When a choice's `if` turns true or false while its menu is on screen, because a flag changed from a spell, a script or a timer, the choice grows open and fades in, or fades out and folds shut, and the choices under it slide along. It used to pop in or out between two frames. A new menu still arrives with the list's own fade, and when the OS asks for reduced motion, choices pop as before.
- **Spot encounters.** A new encounter type `spot` draws a labeled ring at a point of the map. Its label is written in the content, on the encounter's line: `@well{title: "Old well"}`.
- **New Introduction pages:** Your First 15 Minutes, Coming from Ren'Py and Coming from Twine. Both Coming from pages map variables to flags, which need no setup; properties are for advanced use.
- **Saving a map or screen dungeon with a missing image keeps the game in step.** It used to write content_raw.txt but skip content_parsed.json, so the game played older content than the editor showed. Both are saved now, and the editor names the missing image.
- **Edit content outside the editor.** `content_raw.txt` can be written in VS Code, by an AI or by your own tools: the engine brings a dungeon's `content_parsed.json` up to date whenever its text changed – when a dev playtest starts, when the editor opens the game, and on Export. Each parsed file keeps a hash of the text and config it came from, so a dungeon is only regenerated when its content really changed, and a boot where nothing changed only checks file times.
- **Check content from the terminal.** `node engine_files/tools/dryad.mjs check <game>` runs the editor's content checks without the engine and prints each problem as `file:line: severity: message`, with the editor's suggestion where it has one. `parse <game>` regenerates the parsed content of dungeons whose text changed. Writers working outside the editor – an AI agent with only the desktop app – can check their own work.
- **Focus mode.** The Focus button at the left end of the editor's top row, or Ctrl+Shift+F, shrinks the editor's two header rows to one slim strip: where you are, each part a picker, plus Playtest and Continue. In the Content tab the toolbar and search row share one line too. It is remembered per subtab.
- **Play from here stays out of the way.** Its ▷ names itself only when you hover the triangle, not the whole card or column, and the label floats over the header instead of pushing its buttons aside.
- **Big dungeons open fast.** Switching to a large dungeon in the Content tab used to freeze the editor for seconds; the first cards now show in a third of a second and the rest fill in while you work. The content checks no longer re-read the whole game on every switch, only the dungeons involved. Typing in a big dungeon is about three times quicker too: a keystroke no longer re-renders other cards or rewrites the page's stylesheet.
- **The editor fills the window.** Every tab now reaches the bottom edge; a fixed height left a strip of empty space under it.
- **Escape no longer opens the menu by accident.** Escape that closes a dropdown, popover or dialog, or that you press while typing in a field, now stays with it instead of also opening the game menu.
- **Debug panel dropdowns follow its dark theme.** They used to open light over the dark panel.
- **Continue works after a load.** After you load a save or snapshot mid-scene and go straight back to the editor, Continue resumes where you were instead of saying there is no playtest to continue.
- **Content checks with a mod selected.** Names from another dungeon are now read from both the game and the mod, since a mod's dungeon file only adds to the game's. A quest or flag the mod's file leaves out is no longer reported as missing.
- **Scene and row comments are readable in the light theme.** A comment above a scene's first row or a row's first column sat in a dark grey bar with grey text; it now uses the editor theme's colors in both themes.
- **`inventory_open` says which window opened.** Listeners get a second argument, `"loot"` or `"trade"`, so a script can react to trade windows only, for example to put the trader on stage.
- **Buttons in the loot and trade window.** Each panel's title row has a new `exchange-inventory-header` component slot at its right end, before **Loot All**. In a trade window, each side's currency box has an `exchange-currency` slot at the end facing the other panel. The two boxes are always the same height, so a button there never pushes one panel's grid below the other's, as a wide one in a title row does once the row wraps. Components in both get the panel's `inventory`, `targetInventory`, `mode` and `isParty`. The party panel's default title is now **Party**, which leaves its title row room for the weight readout. The new `game.exchangeItem(item, source, target, quantity)` moves an item the way a click does, price and payment included, so a slot button can run a bulk action such as selling every piece of junk.
- **Visual effects: Reduced, for slow machines.** A new engine setting turns off the effects that redraw every frame. Panels lose their frosted-glass blur, and the character sheet and trade window get solid backgrounds instead. The glow on battle targets holds still instead of pulsing, the `glow` and `spooky` text effects stop, and ambient particles are skipped. Blur-in, blur-out and shatter transitions keep their motion but lose the blur. The setting starts on Reduced when the player's OS asks for reduced motion. A game can honor it in its own effects: `<body>` carries the class `reduced-effects`, and `game.getEngineSetting('visual_effects')` reads it.
- **Game CSS can style one character.** Each character on stage carries its id on its slot as `data-char-id`, so a stylesheet can single one out: `.character-slot[data-char-id="nell"] .character-doll-wrapper { … }`. The party list's faces already carried the same attribute.
- **Screen dungeons can have several rooms.** Add rooms in the Rooms tab and connect them with doors, and each room can carry its own **Image**: the picture shown while the player is in it, with the room's own encounters placed on it. The player moves between rooms on the room map from Text dungeons and with the arrows beside the room's description; the picture cross-fades on each move. In the editor, the Rooms tab draws a Screen dungeon's rooms as a graph and the Encounters tab shows one room's picture at a time, picked at the top of the map; an encounter placed there joins that room. A Screen dungeon without rooms still plays in its implicit `main` room, as before.
- **Templates accept every SVG element.** The template check called SVG filter and animation tags such as `<feTurbulence>`, `<feMorphology>` and `<animate>` unregistered components, so a component that drew an SVG filter failed the check. It now knows every SVG 2 element.
- **A game without a plugins folder boots without errors.** A dev boot listed each mod's `plugins` folder and each plugin's `css` folder whether or not it existed, and logged a 404 error for every one that was missing. Missing folders are now skipped.
- **The editor header fits a laptop screen.** On a narrow window the game and mod pickers shorten with an ellipsis, so **Playtest** and **Continue** keep their full labels.
- **Experience: scene XP grows with the character's level.** With `auto_scaling` on, a numeric `{xp: N}` grant is written for level 1 and multiplies by the reward scale at the receiver's level, the same curve fight XP rides. A scene grant used to stay fixed while fights paid more, so by mid-game it was a sliver of a level. It reads the character's level rather than the dungeon's, so a quest finished long after the dungeon was entered still pays its full share. Existing amounts need no change.
- **Pools give every category a fair share.** An entity whose filter names several categories now picks one of them first, then an item in it. Before, every matching item was equally likely, so a category with many items crowded out one with few: twenty rings would drown out two weapons. To favor a category, give it an entity of its own.
- **RPG battler: a default cast gesture.** A caster with no cast pose (no art keyed on `battle_state`, such as a character drawn as a single frame) used to stand still for a `cast` ability with an effect, since the `cast` battle state had nothing to show. It now gathers, rising a little and brightening, then pushes toward its target as the travel sprite launches or the impact appears. Characters with cast frames are unchanged. With Reduced visual effects the motion stays and the glow is dropped.
- **RPG battler: projectiles outside battles.** `game.getService('rpg_projectile').play(id, { from, to })` flies a Projectiles-tab effect between two points on the screen, with its impact, burst and sparks, so a game can show a spell cast in a scene. The game animates its actors itself (`{animate: "bram hurt"}`). See the battler's Projectiles guide, Outside battles.
- **A recipe can retire.** Recipes have a new `if` field, written like a scene choice's `if`. A station lists a learned recipe only while its condition holds, so a one-off quest recipe stops cluttering every bench once the quest is done (`"my_dungeon.quest_done != 1"`). The recipe stays learned; it just stops showing.
- **Experience: battles draw their loot from pools.** The new `battle_loot_pools` setting maps threat bands to pool entries. A won battle draws its band's pool at the dungeon level, the same way a pooled chest does, so what a boss drops can be read straight off its pool. The threat budget rolls and their settings (`loot_equipment_coef`, `loot_income_coef`, `loot_gold_share`, `loot_max_items`, `loot_income_categories`, `loot_currency_item`) are gone. A battle's own drop table still pays on top.
- **Experience: gather tiers follow your items.** Gather spots used fixed tier levels 1/4/7/10. Level 1 and each distinct `spawn_min` among the foragable items now open a tier, so moving an item's spawn window moves the tiers with it.
- **Experience: a retuned XP curve reaches old saves.** The XP a character needs for the next level was saved with them and only recomputed at a level-up, so a changed `xp_base`, `xp_growth` or formula applied one level late. A save now takes the current curve when it loads, and each character keeps their level and the same fill of their XP bar.
- **Experience: the smith station works on worn gear.** Equipped pieces are listed with an **E** tag, and a filter shows all gear, only equipped or only unequipped. Reforging a worn piece unequips it, swaps in the new one and equips it into the same slot, so the wearer's stats update at once and the game's `item_equip_*` listeners run as for any equip. A worn piece also stops at its wearer's level. Each tab has a line telling the player how it works, and the list sorts by level, then rarity, highest first. A bag piece that beats what someone wears (a stat gained, none lost) carries a ▲. **Upgrade equipped** reforges every worn piece in one go, spreading the stones held from the lowest level up. The detail view lists the stats a reforge changes. The station reopens on the tab and filter the player left.
- **Experience: break down several items at once.** On the Break down tab the player marks any number of unequipped pieces (with **Select all**, **Clear**, a chip per rarity and **Up to Lv N**), and one **Break** button breaks them all after a single confirm, showing the total refund. `smith_break` still fires per item, so a veto skips just that piece. The `smith` service gains `breakItems(items)`, `upgradeItems(plan)`, `planEquippedUpgrades(budget)`, `beatsWornGear(item)`, `wearerOf(item)` and `levelCap(item)`, and is typed as `getService('smith')`.
- **Books and scrolls.** An item's new **Readable** field gives it a Read choice. A **Book** opens as an open book over the screen, with pages laid out to fit the window: two side by side on a wide screen, one on a phone, turned with ‹ ›, the arrow keys or a swipe, and a resize keeps the reader on the paragraph they were at. A **Scroll** is a parchment the text scrolls on. Both read a `$template` (source `dungeon_id.template_id`), take placeholders and `if{}`, and mark the item read when they open. A game replaces the art with a `background` on `.readable--spread .readable-paper` and its siblings in its own CSS, and sets fonts, colours and text margins with `--readable-*` variables on `.readable`, or on `.readable[data-item="…"]` for one item. `{read_item: "id"}` opens a readable the player does not carry, and scripts call `game.readItem(item)`.
- **Loot, trade, item-picker and smith choices wear a badge.** A choice that carries `{loot}` shows a chest before its label, `{trade}` a pair of scales, `{choose_item}` a backpack and `{smith}` (experience) an anvil, the same way a fight choice shows crossed swords. The row gets `loot-choice`, `trade-choice`, `choose-item-choice` or `smith-choice`. Hide `.loot-badge`, `.trade-badge`, `.choose-item-badge` or `.smith-badge` in the game's CSS to drop an icon.
- **Experience: text follows the Text size setting.** The smith station, the XP bar on the character sheet and the reward popup's Continue button used fixed pixel sizes, so changing the engine's text size left them as they were. They now scale with it and look the same as before at the default size. The small badges on item bricks stay fixed, like the engine's own quantity labels, since the brick does not grow.
- **Item level on every brick.** An item with an `item_level` trait now shows a small Lv tag in its brick's bottom-left corner everywhere: inventory, equipment slots, item pickers, loot and trade windows, and the reward panel. It used to show only on the item card. On a trade brick it sits apart from the price, so a long price no longer covers it.
- **Item weight lives on the item card.** Bricks no longer show a weight, which left little room on a 64-pixel brick and repeated the same small number on most items. The item card shows it, and for a stack it shows the sum: `Weight: 0.3 × 5 = 1.5`. The weight total in the loot and trade window is unchanged.
- **Sort the inventory.** The inventory window has a sort picker next to the search: **Recent** (newest first), **Name**, **Rarity** (rarest first, quest items after every real tier), **Level** (highest first, then rarest) and, in a game with any weighted item, **Weight** (heaviest stack first). The choice is remembered per browser. Recent reads the new `item.addedAt`, the moment a stack last gained items: `addItem` stamps it, a save keeps it, and unequipping a piece keeps the stamp it was picked up with.
- **Experience: maxed gear stays in the smith's list.** On the Upgrade tab a piece already at its level cap is listed at the end of its group, faded under a MAX badge, instead of vanishing. Its card still opens.
- **Item stats can depend on the slot.** The new `item_stats` emitter gets a copy of an item's stats with the slot and character it sits in (both `null` when loose), and a listener rewrites the copy: a gem's power goes to its socket, an off-hand halves a weapon. The engine applies it everywhere it reads item stats: the equip status, the item card, both sides of a comparison. `game.getItemStats(item, slot?, character?)` gives the same answer to scripts, including "as if it were in this slot", and `ItemCard` takes an `inSlot` prop for that. A game that rewrote stats on `item_equip_after` and undid them on unequip moves that into one `item_stats` listener.
- **Experience: the smith's preview reads the worn slot.** The before and after cards and the list of changing stats show the upgrade as it will be in the slot the piece is worn in, so stats that depend on the slot no longer flip to their loose form in the preview.
- **Experience: the smith station has its own confirm box.** **Upgrade equipped** and **Break** used to ask through the engine's general dialog. They now open a box inside the station panel, with the station's own buttons, so a game that restyles `#smith-station` restyles the box too. Enter confirms, while Escape or a click outside it cancels. The guide lists the classes to target.
- **What's new on the landing page.** The manifest has a new `changelog` field: one entry per release with a version, a date, an optional title and picture, and rich-text notes. The landing page shows **What's new** next to the version, and it opens the list newest first, the latest release expanded, with an **Expand all** / **Collapse all** toggle. Put `[changes]` in a manifest description or a landing widget's `html` and it shows the newest entry there, under a "New in" heading, so a release's notes are written once. A returning player sees a dot on it after an update until they open it. A mod keeps its own changelog in its own manifest, and its panel gets the same link. See Releasing Your Game or Mod.
- **A date field type.** Forms, plugin settings and custom fields can use `date`, a calendar picker that stores the day as `YYYY-MM-DD` text: readable in the JSON, sorted correctly as text, and free of time zones.

### Bug Fixes

- **A plugin no longer resets what the story set.** A game with no save migration of its own got a full one once it used a plugin that declares one, such as reputation, which only keeps its own trait out. Every other stat, trait and attribute went back to its template value on load, on every load in dev mode and after any version bump in a release, so a costume set by the story was lost. The pass now plays the story's writes back after the reset, and a `skip` only takes ids out and never turns a section on.

- **RPG battler: no red portrait for a character with no health.** The party portrait's health overlay read a character with no health at all as having lost all of it and tinted the face red. A game whose cast doesn't fight now shows plain portraits.

### Breaking Changes

- **Every game gets save restoration.** The pass runs without a declaration and, with no `mode`, syncs every section except `itemTraits`. A game that relied on nothing being restored writes `mode: 'opt-in'`, and a declaration with no `mode` that relied on item traits resetting writes `mode: 'opt-out'`. A save made before this version has no record of what the game wrote, so its first restoration syncs every unskipped id to the template. A mod's `only` no longer narrows a section the game's mode already syncs. `runDefaultSaveMigration()` follows the same default.
- **The `book` item trait is now the Scene type of Readable.** A book whose pages run actions works as before: set its Readable to type Scene, with the trait's scene reference as the source. The `read_book` action and locale key are now `read_item`, and a game's `locale.json` can rename the Read label.
- **Experience: the smith station has its own settings tab.** Its break-down divisor and sounds moved out of Experience Config into a new **Smithy** tab (`plugins_data/experience/smith`: `break_divisor`, `sound_open`, `sound_upgrade`, `sound_break`), and the station can now play a sound when it opens. A game that set `smith_break_divisor`, `smith_sound_upgrade` or `smith_sound_break` sets them again in the new tab.
- **`item_compare` is removed, and a worn item's status keeps its own stats.** Both sides of a comparison are now read through `item_stats` in the compared slot, so they already line up, and the emitter that lined them up by hand is gone. Move such a listener to `item_stats`. The status an equipped item grants used to share its stats object with the item, so editing one changed the other; it now holds its own copy, and an edit to it stays on the character.
